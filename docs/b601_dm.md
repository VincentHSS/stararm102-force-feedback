# StarArm Leader → Seeed B601-DM

此入口将 StarArm 102LD/102HD Leader 与 Seeed reBot Arm B601-DM 配对，实现关节跟随、力矩负载反馈、主臂阻尼及堵转锁定。原 `stararm102_ro.py` 仍用于 StarArm 从臂。

## 文件

| 文件 | 用途 |
|---|---|
| `stararm102_b601_dm.py` | 601 入口、终端、运行状态和模拟 |
| `b601_dm.py` | 配置校验、主从映射、达妙串口桥与新回包识别 |
| `configs/b601_dm.example.json` | 七关节配置示例 |
| `stararm102_ro.py` | 复用的 Leader 控制台、阻尼和堵转状态机 |
| `tests/test_b601.py` | 38 项 601 无硬件检查 |

代码依据下列一手接口资料编写，尚未连接真实 B601-DM 验证。串口及协议定义核对于 MotorBridge 提交 `d5700bcd5b7f9355dd2012488d463c3bac982259`：

- [Seeed B601-DM Quick Start](https://wiki.seeedstudio.com/rebot_b601_dm_getting_started/)
- [Seeed 102 + B601-DM 配对教程](https://wiki.seeedstudio.com/sensecraft_robotics_rebot_arm_102_b601_dm/)
- [MotorBridge 达妙串口帧定义](https://github.com/motorbridge/motorbridge/blob/d5700bcd5b7f9355dd2012488d463c3bac982259/motor_core/src/dm_serial.rs)
- [MotorBridge 达妙指令及反馈定义](https://github.com/motorbridge/motorbridge/blob/d5700bcd5b7f9355dd2012488d463c3bac982259/motor_vendors/damiao/src/protocol.rs)
- [Seeed 电机配置](https://github.com/Seeed-Projects/reBotArm_control_py/blob/main/config/rebotarm_dm.yaml)

这里直接使用 `pyserial` 实现标准达妙 USB-CAN 串口桥收发，接收层给每个关节维护帧序号和接收时间，不依赖 SDK 的缓存状态作为新数据。不需要额外安装 MotorBridge；厂商工具用于事先校准与配置设备。

## 1. 环境和硬件准备

```bash
git clone https://github.com/VincentHSS/stararm102-force-feedback.git
cd stararm102-force-feedback
python -m venv .venv
# Linux
source .venv/bin/activate
# PowerShell 改用 .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m serial.tools.list_ports
```

Leader 使用原 Fashion Star UART 接口，默认 1,000,000 baud。601 使用达妙的标准串口桥，默认 921,600 baud；这两个值不是 CAN 总线比特率。本版不支持 SocketCAN、DM_Device USB 模式或 RS 电机版本。

先按 Seeed 流程完成机械安装、电机 ID 和零位校准。在厂商工具内确认七个电机均为 **POS_VEL 模式（RID 10 = 2）**，并设置适合设备的控制参数和通信保护；本程序只读取模式及编码量程，不自动改模式、不写 PID、不清故障、不重设零点、不保存电机参数。

启动前 601 必须处于失能状态并得到支撑；本程序使能后会维持其起始姿态。`q`、Ctrl+C 和异常退出会尝试使 601 失能、Leader 卸力，注意支撑设备。软件保持和串口命令不能替代硬件急停。

## 2. 无硬件验证

```bash
python stararm102_b601_dm.py --check
python stararm102_b601_dm.py --simulate --duration 5
python stararm102_b601_dm.py --simulate --duration 5 --simulate-stall-joint 0
python -m unittest discover -s tests -v
```

无参数默认运行模拟，不打开任何串口。第三个命令模拟 Leader ID 0 对应的从臂关节卡住，预期出现锁定信息。模拟时间为虚拟时间，可快速结束；它验证软件链路，不模拟真实惯量、重力和驱动响应。

## 3. 填写配置

复制 `configs/b601_dm.example.json` 为 `configs/b601_dm.local.json`，修改实际端口。Linux 例如 `/dev/ttyUSB0`、`/dev/ttyACM0`；Windows 例如 `COM3`、`COM4`。本地标定文件被 `.gitignore` 排除。

| 配置 | 含义 |
|---|---|
| `leader_type` | 102LD 或 102HD；HD 读取 `button_id` 的按键 |
| `follower_baud` | 达妙串口桥波特率 |
| `loop_hz` | 控制频率上限，默认 50 Hz，实际受串口读取影响 |
| `read_timeout_s` | 一次从臂完整回包等待，默认 0.05 s |
| `link_timeout_s` | 缺少完整有效样本后进入保持的时间，默认 0.25 s |
| `max_start_error_deg` | 启动姿态匹配容差，按 Leader 等效角度计算，默认 5° |
| `calibration_verified` | 是否已验证方向、比例、零位、限位和负载参考；示例为 false |

每个 `joints` 项定义一个配对：

```json
{
  "leader_id": 0,
  "motor_id": 1,
  "feedback_id": 17,
  "model": "4340P",
  "sign": 1,
  "scale": 1.0,
  "leader_zero_deg": 0.0,
  "follower_zero_rad": 0.0,
  "lower_rad": -2.61,
  "upper_rad": 2.61,
  "speed_rad_s": 0.4,
  "torque_reference_nm": 5.0,
  "torque_floor_nm": 0.1
}
```

示例 CAN ID 为 1–7，反馈 ID 为 17–23；J1–J3 电机为 4340P，J4–J7 为 4310。**示例中的符号、比例、限位和力矩参考并未针对你的设备实测，不能仅把确认字段改为 true 就视作完成标定。** J7 是夹爪电机，不是夹爪开口毫米数；需验证传动方向和可用行程。

启动时读取每个电机的 PMAX、VMAX、TMAX，用于解码实际反馈；它们是协议编码量程，不是机械限位，也不是安全额定负载。

## 4. 采集配对姿态

将已完成零位校准的主从臂放在希望互相对应的姿态，支撑设备后运行：

```bash
python stararm102_b601_dm.py --config configs/b601_dm.local.json --capture configs/b601_pair.local.json
```

此操作只查询设备并保存两侧的当前姿态，不使能、不卸力、不修改驱动器零位。采集结果仍保持 `calibration_verified=false`。

需要逐关节核对：Leader 正向小角度变化对应 601 的哪个方向，角度比例是否正确，夹爪是否会碰到机械边界。修改 `sign`、`scale`、`lower_rad` 和 `upper_rad`，结合厂商的单关节低速验证流程确认。程序不实现末端笛卡尔位姿映射，运动关系是配置中的逐关节映射。

确认后在本地配置设置 `calibration_verified=true`，保持双方在采集的配对姿态附近、601 处于失能状态，再运行：

```bash
python stararm102_b601_dm.py --config configs/b601_pair.local.json --live
```

启动检查依次确认模式、编码量程、所有关节的新回包、温度/状态、机械限位及配对误差。通过后先发送当前姿态目标，再使能并验证回包。程序不自动移动到配对姿态，也不重置 Leader 圈数。

## 5. 日常命令

| 命令 | 601 版本中的含义 |
|---|---|
| `s` / `fb` / `st` | 运行状态 / Nm 反馈 / 堵转状态 |
| `fb on` / `fb off` | 开关力矩到阻尼的映射；不覆盖已有锁定 |
| `fbmax 5,5,5,1,1,1,1` | 各关节参考力矩 Nm |
| `fbmax auto` | 使用衰减峰值作为参考，适合观察 |
| `fbq 0.1` | 统一力矩噪声门槛 Nm，须低于各关节参考值 |
| `fbp 1 1200` | 主臂反馈阻尼范围 mW |
| `fbhz 20` | 阻尼与堵转样本处理频率上限；不提高硬件循环频率 |
| `500` / `3=800` | 手动阻尼；其中 3 为 Leader ID，对应 J4 |
| `l` | 锁 J1–J6，关闭负载反馈 |
| `st lock` / `st unlock` | 手动锁定全部主臂关节 / 恢复原状态 |
| `stop` | 601 保持最近有效反馈姿态，锁定 Leader，进入保持状态 |
| `resume` | 完整新回包和状态恢复后，以当前姿态重新配对并继续 |
| `n` | 601 进入保持，Leader 卸力，关闭反馈和堵转；与原入口的继续跟随不同 |
| `q` / Ctrl+C | 退出，尝试 601 失能、Leader 卸力、关闭端口 |

原有 `stlock`、`strel`、`stn`、`stwin`、`sttrack`、`sttrackmin`、`stload`、`ststatic`、`stscope`、`sthold`、`stmethod`、`strelock` 均可用于普通跟随阶段。参见[命令参考](reference.md)。功率 `0` 仍是舵机协议中的最大保护功率，不是卸力。

通信/电机故障进入保持后，不会自动恢复运动，也不通过 `st unlock` 绕过保持；先排除异常再用 `resume`。`resume` 只重置本次运行的配对基准，不改写磁盘标定文件。`n` 关闭的反馈和堵转功能不会被 `resume` 自动开启，需要另外输入 `fb on`、`st on`。

## 6. 控制与反馈逻辑

```mermaid
flowchart LR
    L[Leader 原始角度 °] --> M[零位 / 方向 / 比例映射]
    M --> V[关节限位与目标速度限制]
    V --> C[601 POS_VEL 指令 rad]
    C --> F[逐关节新反馈帧]
    F --> T[估计力矩 Nm → 负载比例]
    T --> D[Leader 阻尼 mW]
    F --> I[反映射到 Leader 等效角度]
    I --> G[跟随误差 / 观察窗口 / 负载判据]
    G --> H[锁定 Leader 并冻结对应目标]
```

映射为：

```text
q601 = follower_zero_rad + sign × scale × radians(qLeader - leader_zero_deg)
ratio = clamp((abs(torque) - floor) / (reference - floor), 0, 1)
power = round(power_min + ratio × (power_max - power_min))
```

反向映射将从臂角度和实际下发目标换算到 Leader 等效角度；堵转阈值沿用 Leader 度数，不会拿弧度直接与 20° 比较。检测使用经过速度限制后真正下发的目标，减少把主动限速当作从臂跟不上。

默认误差达到 20° 后观察 0.4 s，结合同向跟随比例、误差收敛和 30% 负载门槛，确认后锁定全部主臂关节。锁定时保存对应目标；所有触发关节误差连续 0.3 s 不超过 8°，自动解除。手动锁定和故障保持不按误差自动解除。

采样前先处理已缓存帧作为基线，再主动请求每个电机反馈。只有基线之后新收到的帧才交给本轮控制；角度数值相同但帧序号增加仍算新回包。分包、噪声、外来 CAN ID、寄存器回复和缺少某个关节均有独立处理。旧样本或缺失样本会中断堵转观察和解除计时。

正常目标每步按 `speed_rad_s × dt` 限幅，dt 最大按 0.05 s 计算，防止循环延迟后突然追赶。目标越过配置限位会进入保持；反馈限位允许 0.01 rad 的解码/测量裕量，保持目标仍限制在配置范围内。

## 7. 标定与故障处理

力矩参考默认 5/5/5/1/1/1/1 Nm，只是示例标尺。达妙反馈是电机估计力矩，包含重力、摩擦与动态负载，不能直接解释为外部接触力；本版没有重力补偿或末端力传感器标定。应先记录本机不同姿态下的工作读数，再设置噪声门槛、参考值与堵转负载条件。

- **模式不匹配**：用厂商工具确认七个电机的 RID 10 均为 2，再关闭厂商工具以释放串口。
- **配对误差过大**：回到采集姿态，核对方向和零位；不要靠扩大启动容差跳过错配。
- **反馈缺失**：检查桥接模式、波特率、CAN ID、反馈 ID 和供电；本版本仅支持标准达妙串口桥。
- **锁定但保持力不足**：核对 Leader 保持功率与固件保护值；状态表示软件请求锁定，不代表独立验证了物理锁力。
- **通信超时或状态异常**：停止更新运动目标，尝试锁定 Leader 并保持最近有效姿态。若链路已断开，保持或失能指令可能无法送达，需用设备停止方式处理。

当前对温度 ≥80°C 或电机非使能状态会进入保持，不自动清错。该阈值是本控制器的检查值，不替代厂商的保护参数。
