# 故障排查

## 从臂跟不动，但主臂没有进入锁定

输入 `st` 查看是否启用保护，以及当前误差、负载和判定原因。

| 状态或原因 | 检查方向 |
|---|---|
| 堵转保护 OFF | 执行 `st on`；注意 `n` 会关闭保护 |
| 误差未到锁定阈值 | 核对角度单位、零位与目标；默认需达到 20° |
| 观察中 | 等待观察窗口和确认次数满足，默认至少约 0.4 s 加采样延迟 |
| 从臂仍在跟随 | 看同向位移比例，短时滞后可能不会触发 |
| 误差在缩小 | 从臂被判断为正在收敛 |
| 负载未达门槛 | 用 `fb` 检查参考电流、噪声门槛和实测电流 |
| 电流或角度缺失 | 先排查设备回包，不用旧读数代替 |

临时执行 `st lock` 可单独验证锁定指令路径。它不依赖自动堵转判据，因此能帮助区分检测问题与保持能力问题。

## 已显示锁定，但主臂仍能明显移动

显示“锁定”说明软件建立锁定状态并调用了下发接口，不等于设备确认已达到目标保持力。本程序没有独立的锁定成功回执验证。

检查 `stmethod`、`sthold`、`strelock`，以及实际供电、固件支持和设备功率保护阈值。默认 `both` 同时使用停止保持与位置保持；重发沿用原始保持角度。不要把 `power=0` 当成关闭，也不要无依据地提高功率超过设备允许范围。

重发独立于从臂读取结果，但仍由同一主线程执行。SDK 查询阻塞或串口异常会影响实际重发时机。物理断线时软件不能维持设备的通信控制。

## 一锁住很快又自动解除

先区分手动与自动锁定。`st lock`、`l` 的锁定不因误差恢复自动解除；自动锁定需所有触发关节误差各自连续 0.3 s 回到解除阈值内。正常跟随恢复后解除是预期行为。

如果执行过 `st off`、`st reset`、`st unlock`、`n` 或手动阻尼命令，也会改变已有锁定。`fb off` 保留已锁定关节。

## 快速拖动时误触发

用 `st` 查看跟随比例和观察窗口。适当增加 `stwin` 或 `stn` 可以过滤短时滞后，同时也会延后真实堵转检测。确认从臂供电、串口质量和主从方向后再调参；反向滑动不会被当作正常同向跟随。

## 主臂空载仍有阻力

默认开启电流反馈，最小功率为 1 mW。参考电流过低、门槛不匹配或从臂自身摩擦都可能增加阻尼。

`fb off` 关闭反馈并释放未锁定关节。若仍有锁定，先支撑机械臂，再执行 `st unlock`；如需退出全部主臂控制状态可执行 `n`，但这也会关闭自动堵转检测。

## 串口打不开或监控不完整

```bash
python -m serial.tools.list_ports
```

检查主从端口是否写反、设备是否供电、波特率是否匹配、ID 是否为 0–6，以及是否有其他程序占用串口。HD 模式会额外读取默认 ID 7 的按键板；没有按键板时使用 LD 模式或 `--button_disable`。

Linux 检查用户串口组权限；Windows 使用实际 COM 端口。多从臂中一台缺少某关节回包，会使该关节本轮合并读数无效。

## 频率较低或输入稍有延迟

监控查询是同步的，超时会影响整个控制循环。先处理丢包，再尝试降低 `--fb_hz`。增加从臂数量会增加串口读写耗时。终端输入线程只负责入队，命令需等待主循环处理。

Linux TTY 可原地刷新状态行；Windows 使用简单输入模式。输出被重定向时不每秒打印状态，需要主动用命令查询，或自行增加结构化日志。

## 程序退出后从臂仍保持

退出清理只尝试让主臂卸力和关闭串口，没有专门的从臂停止指令。`n` 同样只控制主臂状态。从臂应按设备自己的停止、卸力与断电流程处理。
